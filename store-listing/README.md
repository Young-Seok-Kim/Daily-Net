## Play Console 입력

대상 패키지: com.youngs.dailynet. 언어 폴더명(`ko-KR`)이 Play 언어 코드다. 영어를 추가하려면 `en-US/` 에 같은 세 파일을 둔다.

- 앱 이름: ko-KR/title.txt (30자)
- 간단한 설명: ko-KR/short-description.txt (80자)
- 자세한 설명: ko-KR/full-description.txt (4,000자)
- 앱 아이콘: ko-KR/icon.png (512×512. `tools/make_icons.py` 가 앱 안의 벡터 아이콘과 같은 원본에서 뽑는다)
- 그래픽 이미지: ko-KR/feature-graphic.png (1024×500. `tools/make_store_shots.py` 가 만든다)
- 휴대전화 스크린샷: ko-KR/screenshots/01.png … (1080×1920, 최대 8장, 파일명 순서대로. 올릴 때 기존 것을 전부 지우고 다시 올린다)
- 태블릿 스크린샷: ko-KR/screenshots-tablet/01.png … (1200×1920, 7인치·10인치 칸에 같은 파일을 올린다)

스크린샷은 실제 폰 캡처(상태바 제거)를 민트·딥틸 배경에 번갈아 얹고 제목·부제를 붙인 것이다 (2026-11-16 리디자인 뒤 재촬영).
합성 스크립트는 `tools/make_store_shots.py`, 제목·부제는 `tools/store-captures/captions.txt` 에 있다.
다시 만들 때는 캡처를 `tools/store-captures/NN-이름.png` 로 두고 스크립트를 돌린다 (캡처 원본은 개인 기록이 들어 있어 커밋하지 않는다).
순서: 홈 / AI 리포트 / 월 정산 / 입력(사진 버튼) / 인바디.

길이 제한은 스크립트가 올리기 전에 검사한다.

Play 검색 순위에서 문안이 할 수 있는 몫은 "검색어와 관련 있다"는 신호까지다. 그 뒤는 설치 수·평점·리뷰·유지율이
결정하므로, 문안을 바꾼 뒤에도 "다이어트"처럼 경쟁이 큰 단어에서 바로 상위에 뜨지는 않는다.
키워드를 반복해 채우는 것은 메타데이터 정책 위반이라 하지 않는다.
카테고리는 공개 페이지의 건강/운동(Health & Fitness)을 유지한다.
태그는 콘솔의 실제 선택지 중 식단·영양·체중 관리 기능과 일치하는 항목만 선택한다. 검색량 검증 없이 특정 태그의 효과를 단정하지 않는다.
웹사이트 항목은 https://dailynet.web.app/ 가 정상 서비스되는지 확인한 뒤 등록한다.

키워드 방향: 식단 기록, 칼로리 계산을 중심으로 음식 사진, 탄단지, 다이어트 식단, 체중 기록을 기능 설명에 자연스럽게 포함했다. 검색량이나 순위 상승을 검증한 키워드 목록은 아니다.

## 검색엔진 등록

- 2026-11-16 네이버 서치어드바이저(계정 `x1682`)에 `https://dailynet.web.app` 을 사이트로 등록해 두고 소유확인은 대기 상태다.
  `hosting/index.html` 의 `naver-site-verification` 메타태그가 배포된 뒤 웹마스터 도구에서 [소유확인] 을 눌러야 끝난다.
- 2026-11-16 구글 서치 콘솔(계정 `seok9562@gmail.com`, 기존 개발자 계정)에 URL 접두어 속성 `https://dailynet.web.app/` 을 추가했다.
  같이 `google-site-verification` 메타태그를 넣어 두었고, 배포 뒤 속성 화면에서 [확인] 을 누르면 소유권이 잡힌다.
  메타태그는 확인 뒤에도 지우면 안 된다(지우면 소유권이 풀린다).
- sitemap.xml 은 hosting 에 있으므로 배포 뒤 `https://dailynet.web.app/sitemap.xml` 로 응답하는지 확인하고,
  서치 콘솔의 Sitemaps 에 제출한다. 네이버는 웹마스터 도구의 [사이트맵 제출] 에 같은 주소를 넣는다.
  등록·제출은 수집 요청일 뿐이고 노출이나 순위를 보장하지 않는다.

스크린샷은 실제 출시 앱과 일치하는 화면을 사용하고 앞쪽에 식단 입력, 칼로리·탄단지 리포트, 월 정산 순서로 배치하는 안을 권장한다. 새로운 이미지 파일은 이번 작업에 포함하지 않았다.

## 배포 및 측정

홈페이지 변경은 웹 검색을 위한 것으로, Play Console 등록정보 수정과 별개다. Hosting만 배포하고 운영 함수나 규칙은 함께 배포하지 않는다.
배포 후 홈페이지, /robots.txt, /sitemap.xml 응답과 모바일 표시를 확인한다.
Search Console의 해당 사이트 소유권이 있으면 sitemap.xml을 제출한다. 사이트맵 제출과 구조화 데이터는 검색 노출이나 리치 결과를 보장하지 않는다.

콘솔에서 변경 직전의 완료된 28일을 기준으로 Google Play 검색 유입의 스토어 방문자, 설치 획득, 전환율, 제공되는 검색어별 실적을 보관한다.
변경 후 같은 길이의 완료된 기간과 비교하고 국가·언어·유입 경로를 맞춘다. 방문자가 적으면 발견 가능성을, 방문은 있는데 설치가 적으면 설명·스크린샷·제품 적합성을 살펴본다. 표본이 적을 때 변화율만으로 효과를 단정하지 않는다.
